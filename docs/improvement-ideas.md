## 3. Security & safety

- **~~Approval callbacks aren't authenticated.~~** — **DONE (2026-07-29)**: `ApprovalGate` now binds each pending approval to the requesting `chat_id` (`core/safety.py`: `_pending` stores `(chat_id, event)` tuples). `resolve()` requires the caller's `chat_id` and rejects the resolution if it does not match the approval's owner, closing the forwarded-message / guessed-id vector. It also no longer writes to `_results` for unknown or expired approval ids, fixing the set-before-registered race. `interfaces/telegram.py` `_on_callback` extracts the callback's `effective_chat.id`, passes it to `resolve()`, and shows an opaque "not valid or expired" message when rejected so an attacker cannot distinguish unknown from wrong-chat approvals.
- **~~HTTP auth = one shared code, unlimited tokens.~~** — **DONE (2026-07-29)**: added `MAX_HTTP_SESSIONS` (default 10) cap so a leaked pairing code cannot mint sessions forever, and `HTTP_PAIR_RATE_LIMIT_RPM` (default 10/min/IP) on `POST /pair` to slow brute-force/minting. Admin endpoints now provide token revocation beyond self-delete: `GET /admin/sessions` lists active sessions with masked token prefixes, `DELETE /admin/sessions/{token}` revokes a specific session, and `DELETE /admin/sessions` revokes all sessions. All require the pairing code and write through to `StateStore`.
- **~~Agent creator executes unvalidated LLM-generated Python.~~** — **DONE (2026-07-29)**: `/newagent` no longer writes LLM output straight to disk. `core/agent_creator.py` now does, in order: `_validate_generated()` runs `ast.parse()` on `agent_py` (and on `tools_stub` when `has_tools`) to catch syntax errors without executing, shape-checks required string fields, enforces `agent.module_name` matches the wizard-chosen name, and rejects skill filenames that aren't lowercase `*.md` basenames (no path separators/dirs) — killing the `../`/absolute-path traversal vector. `_write_agent_files()` keeps an independent basename + regex guard so a bypassed validator still can't escape `skills/`. The wizard gained a `confirm` step: after successful validation it parks the session (`WizardSession.generated`), shows a **preview** (file list + counts + a truncated `agent.py`, capped at 60 lines / 2000 chars) and asks the user to reply `yes`/`y`/`ok`/`confirm` (write) or `no`/`n`/`cancel` (discard, nothing on disk). Refuses anything else at that step. A *real diff* was intentionally not used since generated files are all new (name conflicts rejected up front), so a unified diff would be the whole file marked `+++`; the preview is the honest equivalent.
- **~~No way to clear a pairing lockout.~~** — **DONE (2026-07-19, 2026-07-30)**: `PairingManager.MAX_FAILED_ATTEMPTS` (5) locked a chat_id permanently once persistence landed (§1.4) — `is_locked()` now survives restarts, and `delete_failed_attempts()` is only ever called from the success branch of `try_pair()`, which is unreachable once locked (`core/safety.py`). Added `PairingManager.unlock()` method and `POST /admin/unlock` endpoint (HTTP) to clear lockouts. Telegram interface now also has an `/unlock <chat_id>` command (`interfaces/telegram.py`), restricted to pre-allowed admin chat IDs.
- **~~Rate limiter uses wall-clock time.time()~~** — **DONE (2026-07-19)**: `RateLimiter.is_allowed()`/`wait_time()` now use `time.monotonic()` (`core/safety.py`), immune to NTP jumps/clock changes mid-window.
- **~~Unencrypted DB is silent~~** — **DONE (2026-07-19)**: `main.py`'s `bootstrap()` now logs a warning at startup when `DB_ENCRYPTION_KEY` is unset. Log-only, not fatal in any environment — a visibility fix, not policy enforcement.
  - ~~**⚠️ Deeper bug — [#43](https://github.com/juanfrank77/modular-agents/issues/43) `DB_ENCRYPTION_KEY` set but SQLCipher unavailable → silent plaintext DB.**~~ — **DONE (2026-07-31)**: `apply_encryption_key()`'s (`core/db.py`) guard query was typo'd as `PRAGMA cypher version` — wrong word *and* a space instead of an underscore. Confirmed empirically worse than "misfires and stays silent": against a real (non-SQLCipher) `aiosqlite` connection, that malformed pragma isn't accepted-and-ignored the way an unrecognized-but-syntactically-valid pragma would be — it's a SQL syntax error, so `apply_encryption_key()` raised a confusing `sqlite3.OperationalError` instead of the intended clear `RuntimeError`. Fixed to the correct `PRAGMA cipher_version`, which plain SQLite does accept and returns no rows for, so the intended fail-fast `RuntimeError("...SQLCipher is not installed...")` now fires as designed. `tests/test_db.py` gained a regression test running the real (non-mocked) connection path so the exact pragma string is pinned, not just asserted via mock.
- ~~**[#45](https://github.com/juanfrank77/modular-agents/issues/45) Trust is inferred from chat_id shape.**~~ — **DONE, both string-convention halves (2026-07-31)**:
  - *Approval gate*: `ApprovalGate.request_approval()` (`core/safety.py`) no longer inspects `chat_id.lstrip("-").isdigit()`. It takes an explicit `trusted_interface: bool` param instead, sourced by `Safety.check_action()` from a new `PairingManager.is_trusted_interface(chat_id)` — a set populated by `pair_directly()` (CLI at launch, HTTP's `/pair` and now also `load_sessions()` on restart, so rehydrated sessions don't regress to un-trusted).
  - *Router dispatch*: `RouterNotifier` (`core/notifier.py`) replaced `register_prefix("cli", ...)` / `register_prefix("http_", ...)` string-prefix matching with `register_chat(chat_id, notifier)` / `unregister_chat(chat_id)` — an explicit per-chat_id registry. CLI's fixed chat_id registers once at startup (`main.py`); HTTP's per-session chat_ids register/deregister via new `on_chat_paired`/`on_chat_revoked` callbacks on `HTTPInterface`, fired from every session mint/revoke path (`/pair`, `load_sessions()` rehydration, `DELETE /session`, both admin revoke endpoints, and TTL expiry pruning) so the registry can't outlive or outgrow real sessions. Surfaced and fixed an ordering bug this exposed: `safety.gate.notify_orphaned()` used to run inside `bootstrap()`, before `HTTPInterface` (and its session rehydration) even existed — an orphaned approval for an HTTP chat_id would have silently fallen through to the Telegram notifier and crashed on `int("http_...")`. Moved the call to `main()`, after `http_interface.load_sessions()`.
  - Deliberately *not* literally "a flag carried on `AgentEvent`" as the issue's proposed fix suggested for the approval-gate half — `check_action(chat_id, ...)` is called from several helper methods across 3 agent files that only have `chat_id` in scope, not the originating event, so threading a new field through every one of those signatures was a much larger, unrelated-looking diff for the same result. Recording trust/registration at the one place each is actually established (`pair_directly()`, and the HTTP session mint/revoke callbacks) achieves the same "explicit, not shape-inferred" goal with far smaller blast radius.
  - **Deliberately deferred, not overlooked**: the issue's `/newagent` follow-up — queueing wizard-generated code for an *admin*-only approver instead of letting the requesting chat self-approve via the existing validate+preview+`yes` gate — is a real feature addition (a new admin-authorization concept), not a hardening tweak, and was explicitly scoped out of this pass by request. Still open.
  - Tests: `tests/test_router_notifier.py` (new), `tests/test_http_persistence.py::TestHTTPRouterCallbacks` (new), `tests/test_safety_core.py::TestPairingManagerTrustedInterface` / `TestSafetyCheckActionTrustedInterface` (new). Full suite: 606 passed, 1 pre-existing unrelated flake.
- **~~systemd hardening absent~~** — **DONE (2026-07-19)**: `StartLimitInterval`/`StartLimitBurst` moved to `[Unit]`; added `NoNewPrivileges`, `ProtectSystem=strict`, `PrivateTmp`, a scoped `ReadWritePaths` for the app's `memory/` dir, and `MemoryMax=512M` (`modular-agents.service`). `setup.sh`'s human-user install is unchanged — a dedicated-user install is a separate, larger operational change, explicitly out of scope for this pass.
- **~~Pairing code comparison is not constant-time.~~** — **DONE (2026-07-30)**: Added `PairingManager.verify_code()` (`core/safety.py`) using `secrets.compare_digest` after `strip().lower()` normalization; `try_pair()` now routes through it. Updated `interfaces/http.py` `/pair` and all admin endpoints to use `verify_code()` instead of `!=` / `==`. This closes the timing side-channel for both Telegram and HTTP pairing-code checks.

## 4. Reliability & error handling

- **~~Notifier failures are invisible to callers.~~** — **DONE (2026-07-28)**: `core/protocols.py` now defines `NotificationError` and the `Notifier` protocol documents that delivery methods raise on failure. `core/notifier.py` `_send_with_retry()` retries on Telegram `RetryAfter` with backoff and raises `NotificationError` for unrecoverable errors or excessive flood waits. `TelegramNotifier.send`/`send_media`/`send_with_buttons`/`send_and_get_id`/`delete_message` now raise instead of swallowing. `ApprovalGate.request_approval()` (`core/safety.py`) catches delivery failures, returns `False` immediately, cleans up the orphan event, and attempts a plain-text fallback so the user sees the failure instead of a silent timeout-deny.
- **~~Railway health parsing → hourly alert spam.~~** — **DONE (2026-07-28)**:  `healthy` requires status ∈ `("ACTIVE","SUCCESS","DEPLOYED")` parsed by substring-matching free-text CLI output (`railway.py:292, 301-317`). If the CLI output format shifts, the hourly `incident_watchdog` fires forever. `--json` is not available for the wrapped commands, so free-text parsing remains the only path; test the parsers against CLI output changes.
- **~~`telegram_allowed_chat_ids[0]` as the universal scheduled-message target~~** — **DONE (2026-07-28)**: — empty list → `chat_id=""` and scheduled sends silently vanish. Every agent copy-pastes this landmine (business `agent.py:310`, devops `:455`, wellbeing, librarian, projects). Fix once in `BaseAgent` (see 7.1).
- **~~Storage opens a fresh connection (and re-derives the SQLCipher key) on every query~~** — **DONE (2026-07-28)**: `Storage` now keeps a single long-lived `aiosqlite.Connection` opened during `init()` and reused for every query (`core/storage.py`). The SQLCipher key is applied once at connection setup, and `PRAGMA busy_timeout = 5000` avoids transient lock contention with `StateStore`'s per-query connections. `get_or_create_session` uses `INSERT OR IGNORE` to close the old check-then-insert race. `Storage.close()` is called from `main.py`'s shutdown `finally` block.
  - **~~[#39](https://github.com/juanfrank77/modular-agents/issues/39) Concurrent first-message session race~~** — **already fixed by the above**, verified against current code (`INSERT OR IGNORE` is in place). Filed against pre-fix code; close as stale.
- **~~Approval callbacks aren't cleaned up on stale/timeout resolution~~** — checked against [#41](https://github.com/juanfrank77/modular-agents/issues/41): **already fixed**. `ApprovalGate.resolve()` (`core/safety.py`) now checks `_pending.get(approval_id)` before writing to `_results`, so a stale callback after timeout cleanup is a no-op instead of an orphaned leak. Filed against pre-fix code; close as stale.
- **~~Timezones are inconsistent~~** — **DONE (2026-07-28)**: Added `USER_TIMEZONE` setting (`core/config.py`) defaulting to UTC. `core/timezone.py` provides `load_timezone()`, `now_in_user_timezone()`, and `as_user_timezone()`. `core/quiet_hours.py` now evaluates windows in the user's timezone; `core/scheduler.py` passes the timezone to `CronTrigger.from_crontab()` so cron jobs fire in the same zone. `main.py` calls `_scheduler.set_timezone(settings.user_timezone)` at startup. `agents/wellbeing/agent.py` also uses the user timezone for "already sent today" checks and date-based state so scheduled nudges and internal state agree. 
- **~~Logger config is an ordering trap.~~** — **DONE (2026-07-28)**: `get_logger` lazily configured with defaults, and if any module logged before `main.py` called `configure_logging`, real settings became a silent no-op (`core/logger.py:153-155`). `configure_logging()` now passes `force=True` (clearing `root.handlers` first) so it always applies as authoritative, even after an earlier lazy default `_configure()`. Redaction now covers any field in `_REDACTED_FIELD_NAMES` (`{"content", "text"}`) instead of only the literal `content`; covered by `tests/test_logger_config.py`.
- ~~**[#38](https://github.com/juanfrank77/modular-agents/issues/38) GitHub morning digest shows malformed `#None None` PR entries.**~~ — **DONE (2026-07-30)**: `get_health_summary()` (`agents/devops/tools/github.py`) now filters error-shaped entries out of `open_prs` the same way it already did for `failing_ci` (`extend(p for p in prs if not p.get("error"))`). - **~~Pairing/rate-limit logic is triplicated~~** — **DONE (2026-07-25)**: pairing turned out to be three intentionally different models (Telegram: conversational, tracks attempts remaining; HTTP: token-exchange via `POST /pair`; CLI: auto-paired as trusted) — not unified, since collapsing them would lose real UX differences. - **~~Duplicate _on_message registration in groups 0 and 1~~** — **DONE (2026-07-19)**: confirmed as a live bug, not just a smell — python-telegram-bot evaluates handler groups independently, so every private-chat text message was processed twice (double rate-limit consumption, double agent dispatch, two replies per message). - **~~Telegram reaches into pairing._failed_attempts~~** — **DONE (2026-07-19)**: added `PairingManager.attempts_remaining()` (`core/safety.py`), `interfaces/telegram.py` now calls it instead of the private attr. - **~~No HTTP streaming/SSE~~ and the ~~notifier.get_and_clear() out-of-band capture~~** (`http.py:139-148`) race condition — **DONE (2026-07-25)**: added `POST /message/stream` SSE endpoint to `interfaces/http.py` that streams agent responses in real-time as notifications arrive. Fixed the race condition by adding per-chat_id asyncio.Queue and per-chat_id Lock to `HTTPNotifier` (`core/notifier.py`) — notifications are now streamed via the queue while the agent processes, and `get_and_clear()` is protected by the lock for concurrent requests. `notify_done()` signals stream completion; `stream_queue()` helper yields events for SSE consumption. Added to `RouterNotifier` for proper dispatch.
